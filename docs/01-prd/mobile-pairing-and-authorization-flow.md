# 移动端配对与授权流程（Agent 助手方向）

## 文档速览

这份文档专门说明：
- 移动端配对与授权流程
- 桌面审批和 scope 模型
- 后续扩展二维码接入的基础规则

最后更新：2026-03-12


## 1. 目标

配对流程不只是为了让手机“看电脑状态”，而是为了让手机安全接入个人 Agent 助手体系。

配对成功后，移动端未来应能：
- 发消息给 Agent
- 查看任务与活动
- 查看能力概览
- 在受限边界内触发任务

## 2. 当前策略

第一阶段继续坚持：
- 桌面发起
- 桌面审批
- 移动端只读优先
- 高风险写操作后置

## 3. 配对后的能力层级

### 当前可规划能力
- `chat.read`
- `chat.write`
- `task.read`
- `activity.read`
- `capability.read`
- `device.read`
- `logs.read`
- `relay.read`

### 规划中但后置的能力
- `task.write`
- `relay.control`
- 更高风险的系统控制

## 4. 配对流程

1. 桌面端创建 pairing session
2. 移动端输入或扫码 token
3. 移动端提交 pairing request
4. 桌面端审批 scope
5. 审批通过后，移动端开始拉取首页、聊天、任务等接口

## 5. 产品表达要求

用户应该感知到的是：
- “把手机接入你的 Agent”
- “允许这台手机查看和与你的 Agent 交互”

而不是一堆只有技术用户才看得懂的授权文字。

## 6. 一句话结论

配对流程的产品表达也要围绕 Agent 助手来设计，而不是只围绕设备访问本身。
