# ClawDesk 后续任务规划与开发方向（方向校正版）

## 文档速览

这份文档专门说明：
- 后续阶段的任务规划和方向
- 各阶段优先级与建议顺序
- 适合毕设后继续推进的内容

最后更新：2026-03-12


## 1. 文档目的

这份文档用于统一后续开发方向，确保所有后续工作围绕新的主线推进：

`ClawDesk 是面向大一新生的个人 Agent 助手，而不是单纯设备管理面板。`

## 2. 当前项目基线

当前项目已经具备这些技术底座：
- 桌面端安装与运行基础
- 受管 Runtime
- OpenClaw 兼容层
- Browser Relay 自托管
- 配对中心
- 移动端基础接口
- Android 骨架与首次编译通过

这意味着：
- 底座已经够用
- 现在最需要的是把产品主链路切回 Agent 助手

## 3. 后续开发总方向

建议后续坚持 5 个方向：

### 方向 A：Agent 主链路优先
优先做：
- Chat
- Task Center
- Activity Feed
- Capabilities

### 方向 B：小白优先
优先保证：
- 用户看得懂
- 用户知道下一步做什么
- 用户知道 Agent 当前状态与边界

### 方向 C：移动端是聊天与任务伴侣
Android 不应只做监控页，而应规划为：
- 移动聊天入口
- 移动任务下发入口
- 状态与审批伴侣

### 方向 D：设备、Relay、日志继续保留但退居支撑层
这些能力很重要，但不再继续占据主导航中心。

### 方向 E：每轮都可验证、可交接、可继续
所有变更都要回写文档和进度。

## 4. 后续阶段规划

## 第一阶段：桌面 Chat MVP

目标：
- 用户能通过桌面端和 Agent 对话
- 聊天成为主入口

建议任务：
1. 设计 conversation / message 数据结构
2. 新增 Chat 页面
3. 新增 Chat API
4. 把首页从“系统摘要”改为“Agent 首页”

## 第二阶段：桌面 Task Center

目标：
- 用户能把聊天请求沉淀成任务
- 用户能看到当前任务与历史任务

建议任务：
1. 新增任务状态机
2. 新增任务列表与详情
3. 支持从聊天创建任务
4. 支持失败原因解释

## 第三阶段：桌面 Activity Feed

目标：
- 用户能看见 Agent 最近做了什么
- 审批和异常进入统一活动流

建议任务：
1. 设计 activity entry 结构
2. 聚合任务、审批、Relay、错误事件
3. 活动流页面落地

## 第四阶段：Capabilities 目录

目标：
- 用户能看见当前模型、技能、工具

建议任务：
1. models 目录可视化
2. skills 目录可视化
3. tools 目录可视化
4. 说明可用性与授权状态

## 第五阶段：Android Companion

目标：
- Android 成为可聊天、可查看任务、可看状态的陪伴端

建议任务：
1. base URL 配置
2. 首页自动刷新
3. Chat 入口
4. Pairing request 真联调
5. 任务摘要页

## 5. 新的优先级清单

### P0
1. 桌面 Chat
2. 桌面 Task Center
3. 桌面 Activity Feed
4. Models / Skills / Tools 概览
5. Android base URL 与首页接通

### P1
1. Android Chat
2. Android 任务下发
3. Android Pairing 完整流
4. 审批与能力解释增强

### P2
1. 告警页
2. 设备详情页
3. 日志检索增强
4. 自动化任务入口增强

## 6. 明确后置的内容

以下能力先不抢：
- 复杂进程控制
- 高风险系统写操作
- 过重的设备页细节
- 复杂 Browser Relay 控制面板
- 多用户协作体系

## 7. 推荐的开发顺序

后续建议按这个顺序推进：

1. 桌面 Chat
2. 桌面 Tasks
3. 桌面 Activity
4. 桌面 Capabilities
5. Android Home / Settings
6. Android Chat / Pairing
7. 再继续补 Devices / Logs / Alerts

## 8. 一句话结论

ClawDesk 后续所有规划，都要围绕这条主线：

`让用户把它当成自己的个人 Agent 助手，而不是一个复杂的系统控制台。`
