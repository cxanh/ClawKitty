# 毕业设计 MVP 范围说明

## 文档速览

这份文档专门说明：
- 毕业设计 MVP 必须交付的范围
- 当前优先收口的基础功能
- 明确延期到后续开发的功能
- 当前开发时应该遵循的取舍原则

最后更新：2026-03-12

## 1. 文档目标

这份文档用于把 ClawDesk 收敛成一个适合毕业设计交付的 MVP。

从当前阶段开始，项目的核心目标是：

- 可演示
- 稳定
- 便于答辩讲解
- 能在干净的 Windows 机器上安装和运行

这也意味着，后续开发不再优先扩张功能面，而是优先保证主链路讲得清楚、跑得稳定。

## 2. MVP 定位

ClawDesk 是一个面向大一新生的桌面优先个人 Agent 助手。

毕业设计阶段需要明确展示：

1. 用户可以和 Agent 对话
2. 用户可以看到 Agent 正在做什么
3. 用户可以管理任务和提醒
4. 用户可以理解能力边界和权限边界
5. 用户可以使用新手友好的文件查找工作台
6. 软件可以在没有预装 OpenClaw 的 Windows 电脑上运行

## 3. 必须完成的范围

### 3.1 桌面基础

- 可安装或可直接运行的桌面程序
- 应用自管数据目录
- 首次启动引导
- 启动时不依赖 OpenClaw 预安装
- 托盘与受管 Runtime 启动

### 3.2 Agent 主链路

- Home
- Chat
- Tasks
- Activity
- Capabilities
- Permissions

### 3.3 提醒与课表基础

- memory reminder plan
- 桌面提醒投递
- 课程表看板
- 粘贴式课表导入
- 基于课表的课程提醒投递

### 3.4 设备与 Runtime 支撑

- 保留 Devices 面板
- 多设备概览
- Runtime 状态
- Relay 状态
- 系统摘要

### 3.5 文件工作台基础

- 从 safe action 创建 file workspace
- 本地只读搜索
- 分组搜索结果视图
- Everything 可选加速
- 只读整理建议
- 只读整理预览

## 4. 毕设演示主叙事

推荐答辩演示顺序：

1. 打开 ClawDesk
2. 在 Home 说明这是一个 Agent-first 的桌面入口
3. 在 Chat 中展示：
   - 提醒类问题
   - 学习计划类问题
   - 文件查找类问题
4. 在 Tasks 中展示：
   - 任务卡
   - safe actions
   - reminder plans
   - study roadmaps
   - course schedule
   - file workspace
5. 在 Activity 中展示可解释性
6. 在 Capabilities 和 Permissions 中展示边界
7. 在 Devices 中展示支撑控制台和多设备能力

## 5. 明确延期的功能

这些内容应该继续留在文档和接口设计里，但不是当前毕业设计必须交付的范围：

- 多 Agent 运行时
- Android 完整能力闭环
- 小程序客户端
- 文件自动移动 / 自动重命名 / 自动删除
- 更深入的 Browser Relay 控制
- 更深入的进程 / 系统控制自动化
- 更广范围的真实模型编排
- 完整插件生态或模型市场

## 6. 延期但保留接口和文档的方向

这些方向建议继续在文档和 API 里保留，但可以后续再实现：

- 文件整理执行 API
- 移动端审批摘要
- Android 聊天和任务深度交互
- 小程序 bootstrap 客户端
- 与 EverythingToolbar 生态的更深集成
- 更丰富格式的课表导入

## 7. 毕设交付标准

在毕业设计语境下，“完成”意味着：

1. 桌面程序能在 Windows 上安装或运行
2. 主链路页面都可演示
3. 产品叙事是完整的
4. 权限和审批逻辑是可解释的
5. 文档与当前实现保持一致

## 8. 当前开发原则

当“继续扩展功能”和“继续稳定基础功能”发生冲突时，选择：

`优先稳定和讲清楚基础功能`

## 9. 当前推荐优先级

1. 优化 Home 和核心导航，让演示更顺
2. 稳定 Chat / Tasks / Activity / Permissions / Devices
3. 完善用户手册和部署运维文档
4. 准备演示脚本、验收清单和演示数据
