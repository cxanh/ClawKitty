# ClawDesk 实施路线图（Agent 助手方向）

## 文档速览

这份文档专门说明：
- 项目阶段性实施路线和里程碑
- 功能推进顺序与依赖关系
- 作为历史路线图的参考价值

最后更新：2026-03-12


## 1. 文档目标

这份路线图用于把项目从当前已完成的技术基础，推进到真正符合产品方向的 Agent 助手形态。

新的路线图不再以“设备页 / 监控页优先”为核心，而是围绕：
- Chat
- Tasks
- Activity
- Capabilities
- Mobile Companion

组织开发顺序。

## 2. 当前可复用基础

我们已经完成的内容不会作废，而是作为新方向的底座：
- Windows 安装包与目录包
- 桌面端受管 Runtime
- 应用自管数据目录
- Browser Relay 自托管
- OpenClaw 兼容层
- 日志、审计、配对中心、移动端基础接口
- Android 工程骨架与首次编译通过

## 3. 实施原则

### 3.1 先做主产品链路，再补支撑页细节

主产品链路现在定义为：
- 对话
- 任务中心
- 活动流
- 能力目录

### 3.2 小白优先

每一轮开发都要问：
- 大一新生第一次打开时能不能看懂
- 这个能力是不是必须以更简单的文案表达
- 有没有先给出“下一步做什么”而不是一堆技术状态

### 3.3 先桌面 Agent 主站，再移动伴侣

桌面端先成熟为 Agent 主站，Android 再接聊天和任务。

### 3.4 所有能力都要能解释

Agent 不只是“能执行”，还要：
- 能解释自己正在做什么
- 能展示当前可用模型 / 技能 / 工具
- 能告诉用户为什么失败

## 4. 推荐阶段划分

## 阶段 A：方向收口与信息架构重构

目标：
- 统一产品方向文档
- 把主导航和信息架构调整为 Agent 助手思路
- 明确桌面端与 Android 端的核心页面

交付物：
- 方向校正后的设计方案
- 功能清单
- 技术架构文档
- Android 需求文档

完成标准：
- 所有规划文档围绕个人 Agent 助手统一表达

## 阶段 B：桌面 Chat MVP

目标：
- 桌面端出现真正的聊天入口
- 用户能通过聊天触发 Agent 请求
- 会话与消息能持久化

交付物：
- Chat 页面
- conversation / message 基础数据结构
- Chat API 第一版

完成标准：
- 用户能在桌面端和 Agent 对话

## 阶段 C：桌面 Task Center MVP

目标：
- 聊天请求能落成任务
- 用户能看到当前任务和状态变化

交付物：
- Task Center 页面
- 任务状态机
- 当前任务列表 / 历史列表

完成标准：
- 用户能回答“Agent 现在在做什么”

## 阶段 D：桌面 Activity Feed MVP

目标：
- 把任务执行过程转成用户可读活动流
- 审批与错误进入活动流

交付物：
- Activity 页面
- activity feed 聚合逻辑
- 审批事件和错误解释

完成标准：
- 用户能看懂最近发生了什么，而不是只能看原始日志

## 阶段 E：Capabilities MVP

目标：
- 让用户看见当前可用模型、技能、工具

交付物：
- Models 页面
- Skills 页面
- Tools 页面
- 能力状态与解释

完成标准：
- 用户能看懂 Agent 当前“会什么、能做什么”

## 阶段 F：Android Companion MVP

目标：
- Android 成为移动陪伴入口，而不是只读监控器

交付物：
- Base URL 配置
- Home 状态页
- Chat 入口
- Pairing 入口
- 基础任务状态页

完成标准：
- 用户能在手机端查看状态并与 Agent 对话

## 阶段 G：安全与审批收口

目标：
- 高风险动作解释清楚
- 审批流清楚
- 审计与撤销路径清楚

交付物：
- Approval 页面或活动区块
- 更清晰的审批解释
- 审计和异常回顾

## 5. 当前最优开发顺序

基于新的产品方向，建议后续按这个顺序推进：

1. 桌面 `Chat`
2. 桌面 `Task Center`
3. 桌面 `Activity Feed`
4. 桌面 `Capabilities`
5. Android `Base URL + Home + Chat`
6. Android `Pairing + Task`
7. 再补更细的监控、日志、设备详情

## 6. 现有模块的新角色

### Devices
不再是主产品入口，而是运行环境与移动端配对支撑页。

### Logs
作为排障入口存在，不作为主叙事首页。

### Browser Relay
作为工具执行能力的一部分存在，不需要继续单独作为产品主方向推进。

## 7. 近期里程碑建议

### 里程碑 1
- 桌面端 Chat 页面可用
- 基础会话存储可用
- 新手首页改为 Agent 首页

### 里程碑 2
- 任务中心可用
- 活动流可用
- 能力目录第一版可用

### 里程碑 3
- Android 端 base URL 配置页
- Android 首页自动刷新
- Android 聊天入口

## 8. 一句话结论

未来的开发路线应该明确改成：

`先做能聊天、能布置任务、能看懂 Agent 的主链路，再补监控和设备支撑能力。`
