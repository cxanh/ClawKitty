# 移动端首页信息架构（Agent 助手方向）

## 文档速览

这份文档专门说明：
- 移动端首页应该展示什么
- 状态、提醒和审批摘要的优先级
- 与桌面首页的职责分工

最后更新：2026-03-12


## 1. 目标

移动端首页不再只是回答“电脑在线吗”。

它还需要回答：
1. Agent 是否在线、是否忙碌
2. Agent 当前在做什么
3. 是否有任务需要关注
4. 是否有告警或审批需要处理
5. 用户下一步最适合点哪里

## 2. 首页模块建议

### A. Agent 状态卡
- Agent 是否在线
- 当前状态（空闲 / 忙碌 / 等待审批 / 异常）
- 当前会话数 / 当前任务数

### B. 当前任务卡
- 正在执行的 1 到 3 个任务
- 每个任务一句摘要
- 状态标签

### C. 最近活动卡
- 最近 3 到 5 条活动流
- 例如：
  - “已开始整理资料”
  - “等待你批准文件操作”
  - “课程总结已完成”

### D. 能力摘要卡
- 当前模型数量
- 当前 Skill 数量
- 当前 Tool 数量
- 是否存在不可用能力

### E. 设备与 Relay 摘要卡
- Runtime 状态
- Relay 状态
- 心跳时间
- 是否需要回桌面处理

### F. 告警与审批卡
- 最新告警数
- 等待审批数
- 一键进入对应页面

## 3. 首页入口动作

首页应优先提供这些入口：
- `继续聊天`
- `查看任务`
- `查看活动`
- `查看能力`
- `去配对`

而不是让系统监控图表占满首页。

## 4. 数据来源建议

首页第一阶段可继续主要依赖：
- `GET /api/v1/mobile/overview`
- `GET /api/v1/mobile/alerts-summary`
- `GET /api/v1/mobile/pairing-status`

后续需要新增：
- `GET /api/v1/activity`
- `GET /api/v1/tasks`
- `GET /api/v1/capabilities/*`

## 5. 设计原则

- 先显示 Agent 与任务，再显示设备与系统
- 先显示可行动信息，再显示技术状态
- 页面语言尽量口语化

## 6. 一句话结论

移动端首页现在应被定义为：

`Agent 状态总览页，而不是远程设备监控页。`
