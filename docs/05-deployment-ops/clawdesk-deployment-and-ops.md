# ClawDesk 部署运维文档

## 文档速览

这份文档专门说明：
- 项目的部署、运行和排障方式
- 安装包、目录版和数据目录说明
- 没有开发环境时如何运行程序

最后更新：2026-03-12


## 1. 文档目标

这份文档用于说明当前项目如何打包、安装、启动、运行和排障。当前阶段以毕业设计 MVP 交付为主，因此重点不是构建复杂运维体系，而是保证：

- 程序能稳定启动
- 演示路径清晰
- 出现问题时能快速定位
- 新手电脑没有 OpenClaw、没有开发环境时也能运行

## 2. 当前交付形态

当前桌面端主要交付形态包括：

- `win-unpacked` 目录版
- Windows 安装器
- 便携版安装产物

毕业设计演示阶段优先使用目录版，原因是：

- 路径稳定
- 不需要临场重装
- 更方便快速确认程序、日志和数据目录
- 出现异常时更容易回退到已验证版本

## 3. 当前推荐运行方式

当前推荐直接使用目录版入口：

- `C:\Users\ASUS\Desktop\openlaw\clawdesk\apps\desktop\release\0.1.0\win-unpacked\ClawDesk.exe`

运行时由桌面端主进程拉起受管 Runtime。当前重点特性：

- 不要求用户安装 Node.js
- 不要求用户安装 OpenClaw
- 首次启动自动初始化应用数据目录
- 可在空目录和旧数据导入两种路径下启动

## 4. 当前关键目录

### 4.1 项目目录

- `C:\Users\ASUS\Desktop\openlaw`

### 4.2 桌面程序目录版

- `C:\Users\ASUS\Desktop\openlaw\clawdesk\apps\desktop\release\0.1.0\win-unpacked`

### 4.3 正式文档目录

- `C:\Users\ASUS\Desktop\openlaw\docs`

### 4.4 应用数据目录

当前桌面端使用应用自管数据目录。没有 OpenClaw 的新机器上也能自动初始化，而不是依赖用户预先装好 OpenClaw。

### 4.5 日志目录

运行后应能持续看到日志文件写入，便于答辩前定位问题。日志能力目前主要用于：

- 程序启动异常排查
- Runtime 在线状态判断
- 演示前快速确认系统是否稳定

## 5. 演示前建议检查项

建议每次正式演示前确认：

1. 程序能正常打开
2. 首页能显示摘要
3. Runtime 在线
4. Tasks / Activity / Permissions / Devices 可打开
5. 日志目录没有持续报错

如果还要演示增强项，再继续检查：

- Browser Relay 是否连通
- Everything CLI 加速层是否可用
- Android 端是否需要参与演示

## 6. 排障顺序

如果现场发现异常，建议按这个顺序排查：

1. 先确认程序是否能正常打开
2. 再确认首页是否能显示摘要
3. 再确认 Runtime 是否在线
4. 再确认 Tasks / Activity / Permissions / Devices 是否可打开
5. 最后再排查 Browser Relay、Everything、Android 等增强项

这样做的原因是：这些增强项都不是当前毕设 MVP 的主通过条件，不应影响主线演示。

## 7. 毕设阶段的交付原则

当前阶段不追求复杂运维体系，而是追求：

- 启动稳定
- 目录清晰
- 运行路径可解释
- 故障容易定位
- 文档能够说明白当前边界

一句话来说，当前部署运维目标是“能稳定交付、能稳定启动、能稳定答辩”。
