# 毕业设计演示脚本

## 文档速览

这份文档专门说明：
- 毕业设计答辩推荐的演示顺序
- 每一段应该讲什么内容
- 建议现场展示哪些页面和示例数据
- 如果外部依赖异常，应该如何平稳降级

最后更新：2026-03-12

## 1. 文档目标

这份文档给出当前 ClawDesk 的推荐答辩演示顺序，目标是：

- 演示稳定
- 叙事清楚
- 突出“面向大一新生的个人 Agent 助手”
- 尽量少依赖现场不稳定条件

## 2. 演示前准备

建议提前在项目目录执行：

```bash
npm run demo:seed:clean
```

- Activity 时间线

## 3. 推荐总时长

建议控制在：

- 8 到 12 分钟

## 4. 推荐演示顺序

### 第一步：打开 Home

展示：
- Agent 首页总览
- 最近会话摘要
- 当前任务焦点
- 最近活动
- 权限与设备状态

讲解重点：
- 这不是传统设备监控首页
- 这是一个以 Agent 为中心的个人助手入口

推荐说法：

> ClawDesk 的核心不是单纯监控电脑，而是把“和 Agent 对话、看 Agent 正在做什么、把结果沉淀成任务和提醒”统一到一个桌面入口里。

### 第二步：进入 Chat

展示：
- 已准备好的示例对话
- 一条课程提醒类问题
- 一条学习计划类问题
- 一条文件整理类问题

讲解重点：
- Chat 是产品入口
- Agent 回复不是一次性文本，而是会继续沉淀成结构化成果
- 当前采用 `provider-first + fallback-safe`

推荐说法：

> 即便现场没有配置 AI token，系统也不会完全失效，而是保留可解释的 fallback 路径，保证主链路可演示。

### 第三步：进入 Tasks

展示：
- Agent Task Board
- Safe Action Board
- Reminder Plans Board
- Study Roadmaps Board
- File Workspace Board
- Course Schedule Board

讲解重点：
- Chat 的结果会进入任务工作台
- 用户可以持续跟进 Agent 的后续成果

推荐说法：

> 这个页面体现了项目最关键的设计：AI 结果不会停留在聊天框里，而是会沉淀成任务、提醒、学习路线图和文件工作台。

### 第四步：进入 Activity

展示：
- 最近活动时间线
- 审批相关事件
- 文件工作台预览事件
- 提醒计划、学习路线图等创建事件

讲解重点：
- Activity 用来回答“Agent 最近做了什么”
- 它增强了系统的可解释性和用户信任

### 第五步：进入 Capabilities

展示：
- Models
- Skills
- Tools
- 当前状态标签

讲解重点：
- 系统明确区分 `available / partial / planned`
- 不会假装未实现能力已经可用

### 第六步：进入 Permissions

展示：
- 默认风险策略
- 工具级策略
- 待审批请求
- 审批历史

讲解重点：
- 低风险动作可自动
- 中风险可询问
- 高风险必须审批

推荐说法：

> 这个模块体现了项目不是只追求 AI 能力，而是同时重视安全边界和可治理性。

### 第七步：进入 Devices

展示：
- 宿主机状态
- 多设备数量
- Pairing Center
- 设备详情

讲解重点：
- 设备管理面板被保留为支撑控制台
- 未来可承接 Android 和多设备协同

### 第八步：展示文件工作台

展示：
- 文件搜索
- 时间分组
- 事件分组
- 整理建议卡片
- 整理预览

讲解重点：
- 当前阶段优先做“先查找、先建议、先预览”
- 不直接做高风险自动整理

## 5. 现场异常的备用说法

### 5.1 没有 AI token

说法：

> 当前版本采用 provider-first + fallback-safe 结构，保证即使没有 token，核心交互链路仍然可以稳定演示。

### 5.2 Browser Relay 不稳定

说法：

> Browser Relay 属于增强能力，不影响本次毕业设计 MVP 的主链路展示。

### 5.3 Everything 未启用

说法：

> Everything 只是本地文件搜索的可选加速层，未启用时系统仍可使用内置搜索。

### 5.4 Android 未联调

说法：

> Android 当前已完成工程骨架和主要信息面同步，本次毕业设计以桌面端 MVP 为主交付物。

## 6. 结束陈述

推荐结束语：

> 在这个项目里，我把重点放在了把一个 AI 助手真正落成“对新生友好、可解释、可持续跟进”的个人 Agent。当前 MVP 的重点是三个词：可用、可见、可控。
